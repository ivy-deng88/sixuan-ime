# Fcitx 5 本地拼音兼容实施计划

## 目标与结论

本计划采用**专用 Fcitx 5 插件**，而不是把普通 `fcitx5-rime` 换个名字显示为“思玄拼音”。对于希望保留思玄现有拼音体验、但暂不需要语音和云服务的用户，这比单纯复用 `fcitx5-rime` 更合适：它可以继续复用项目的 Rime 方案、候选排序、个人词条和设置，同时接入 Fcitx 5 的输入上下文和候选窗。

第一阶段只以**本地拼音可用且稳定**为验收目标。语音、云候选和在线服务不作为交付要求；不应为了实现拼音而自动开启网络功能。此方案仍需开发和测试，不能直接使用当前官方 IBus DEB 实现。

## 第一阶段功能范围

### 必须支持

- Fcitx 5 能发现并添加“思玄拼音”，可与系统已有 `fcitx5-rime` 共存。
- 拼音输入、预编辑显示、本地 Rime 候选、数字选词、空格选词、翻页和候选点击。
- Shift 单独按下切换中英文；英文模式和普通快捷键正常透传。
- 删除、取消、提交、输入框焦点切换和输入法切换的基本行为与现有 IBus 版本尽可能一致。
- 使用思玄现有的 Rime 数据目录、拼音方案及已配置的本地词库；保留个人词条和学习逻辑。
- 密码、PIN 或其他敏感输入框不收集拼音、不显示候选，也不进行词条学习。
- 安装、退出、守护进程不可用或重启时，Fcitx 不崩溃，不无限等待，普通按键能够正常输入。
- 保持现有 IBus 功能和安装路径可用，不强制用户卸载 Fcitx 5 或 IBus。

### 暂不交付

- 语音录制、识别、长按 Ctrl 和语音文字回填。
- 云候选、文字整理、在线词库同步和其他网络服务。
- GNOME IBus 候选窗皮肤在 Fcitx 5 中的移植。第一阶段使用 Fcitx 5 自身的候选窗和主题。
- GNOME、KDE、X11 等所有桌面环境的全面兼容承诺；首要验证环境为 Ubuntu 26.04、GNOME Wayland、Fcitx 5。

即使用户已有配置启用了云候选，Fcitx 5 第一阶段也应明确跳过云请求；不应在用户不知情时发送拼音。之后如需支持云功能，应作为单独、可选择的功能设计。

## 与简单复用 `fcitx5-rime` 的区别

`fcitx5-rime` 可以提供 Rime 基础拼音，但不会自动复用思玄自己的候选合并顺序、个人词条学习、扩展词库选择和设置。专用插件仍然使用 Rime 作为本地引擎，却由思玄项目控制输入行为，因此更有机会保持原有基础体验。是否完全一致需要通过对照测试确认，不能仅凭使用同一个 Rime 库就保证。

## 推荐架构

```text
Fcitx 5 插件                         sixuan-ime 守护进程
┌──────────────────────────┐         ┌────────────────────────────┐
│ 接收按键和焦点事件       │  D-Bus  │ 持有 librime 和 Rime 会话  │
│ 显示预编辑与候选         │ ◄─────► │ 本地方案、词库和候选排序   │
│ 向当前输入框提交文字     │         │ 个人词条和学习             │
└──────────────────────────┘         └────────────────────────────┘
```

设计原则：

1. **插件不直接链接 `librime`**。Rime 由独立的思玄守护进程持有，避免与同一 Fcitx 进程内已有的 `fcitx5-rime` 争用 Rime 全局状态。
2. 每个 Fcitx 输入上下文使用独立会话，候选和预编辑不能串到其他输入框。
3. 每次输入状态变化带会话标识和修订号；旧候选点击、旧回复不能修改新状态。
4. 原有 IBus 前端继续使用相同的本地拼音行为。长期应把共享的 Rime、按键处理、候选合并与学习逻辑提取成前端无关核心，而不是长期维护两份逻辑。
5. D-Bus 请求必须有超时、断线恢复和明确的按键处理规则。异步设计要特别处理按键顺序：不能在按键已被 Fcitx 消费后，再把迟到的“未处理”结果当作可透传事件。

## 当前工作树已有内容（原型，尚未完成）

以下是截至编写本文时的本地工作树，不代表已发布功能，也不保证已经可用：

| 文件 | 已尝试的内容 | 状态 |
|---|---|---|
| `fcitx5/sixuan.cpp` | Fcitx 5 插件骨架、按键转发、预编辑、候选显示与点击，以及早期语音接口 | 原型；C++ 编译未通过，尚无桌面实测 |
| `fcitx_pinyin.c` | 守护进程侧 Fcitx 拼音会话、Rime 调用、本地候选与部分按键处理 | 原型；与 `pinyin.c` 存在重复逻辑，需提取或做行为一致性验证 |
| `fcitx_bridge.c`、`fcitx_protocol.h` | 插件与守护进程之间的 D-Bus 方法、状态格式和注册辅助代码 | 原型；缺少完整的生命周期、时序与安全验证 |
| `pinyin_core.h`、`pinyin.c` | 暴露部分 Rime 会话辅助接口，并尝试将 Fcitx 候选接入现有回调 | 部分完成；尚不是完整的前端无关核心 |
| `desktop.c`、`native.h` | 尝试让守护进程在没有可用 IBus 引擎宿主时继续运行，并增加 Fcitx 协议入口 | 原型；改变了 IBus 启动路径，必须做回归测试 |
| `fcitx_setup.go` | Fcitx 环境检测与注册辅助函数 | 原型；尚未接入完整的 `setup` 流程 |
| `packaging/fcitx5/` | 插件元数据、输入法元数据和 D-Bus 激活文件草稿 | 草稿；现有 `packaging/build-deb.sh` 尚未安装这些文件 |
| `app.go`、`input_keys.go`、部分桥接代码 | 曾为 Fcitx 语音和 Ctrl 手势尝试接入 | 不属于本阶段目标；实施前应评估并移除或隔离这些未完成路径 |
| `pingyin.sh` | IBus / Fcitx 5 会话切换脚本 | 与原生 Fcitx 插件无关；不是插件本身 |

现有 `Makefile`、DEB 构建脚本和 CI **尚未完成 Fcitx 插件的构建、依赖和打包接入**。当前官方安装包不会因为这些工作树文件自动获得 Fcitx 5 支持。

## 已知验证结果与风险

- 本机使用下载到临时目录的 Ubuntu 开发头文件，针对当前部分 C 文件运行过 `gcc -fsyntax-only`，该检查通过；这只说明语法可通过，不代表链接或运行正确。
- Fcitx 插件的 C++ 语法检查未通过。Ubuntu 26.04 的 Fcitx 5.1.19 头文件要求至少 C++20；当前原型还有键名命名空间、日志级别和 GDBus 参数等编译问题，需修复后重新验证。
- 最近一次 `go test ./...` 有三个本地词库测试失败；本机已安装的官方包带有系统内置词库，可能影响了这些测试的默认假设。原因尚未完全确认，需要在隔离环境中复现，不能将失败直接归因于本次原型。
- 当前原型包含同步 D-Bus 调用，守护进程故障或响应过慢时可能影响 Fcitx 输入响应；需要解决阻塞、超时和消息顺序问题。
- 当前候选选择协议还没有完整的候选修订号校验；焦点变化、候选更新或进程重启后可能出现过期操作。
- 当前语音回填原型尚不能证明始终提交到录音开始时的同一输入框，也未完成安全验证；本阶段不启用它。
- IBus 断开后重连、服务名称冲突及系统已运行 `fcitx5-rime` 的情况均未完成端到端验证。

## 实施步骤

### 1. 收敛范围并建立可重复构建

- 保留现有工作树作为原型，先检查每处改动；不要覆盖用户已有工作。
- 将语音/云相关的未完成入口从本阶段运行路径中移除或显式禁用，不影响原有 IBus 语音功能。
- 增加 Fcitx 插件构建目标，使用 Ubuntu 26.04 的 Fcitx 5 开发包和 C++20。
- 修复插件当前编译错误；确认插件不链接 `librime`。
- 在隔离构建环境运行现有测试，厘清词库测试失败是否与系统安装的内置词库有关。

### 2. 提取或统一本地拼音核心

- 将 Rime 初始化、会话、按键处理、候选合并、候选选择、模式切换和学习逻辑整理为前端无关接口。
- IBus 和 Fcitx 适配层分别负责把核心结果转换为各自的候选、预编辑和文本提交。
- 保留现有候选顺序、去重、Rime 候选索引以及个人词条来源标记。
- 词库或方案变更只在当前组合为空时切换，避免正在输入的拼音被丢弃。
- 明确 Rime 光标位置与 Fcitx 预编辑光标使用的字节/字符单位，避免中文光标错位。

### 3. 完成 Fcitx 会话及 UI

- 为输入上下文创建、重置和关闭会话；处理焦点丢失、输入法切换、输入框销毁及敏感属性变化。
- 实现本地拼音、候选选择和点击，确保一次按键只处理一次。
- 为候选选择添加会话标识与修订号；过期选择应被拒绝并刷新 UI。
- 完善守护进程不可用、超时、退出与重启后的行为，避免卡住 Fcitx 或重复提交文字。
- 明确普通按键、修饰键组合及中英文模式下的透传策略。

### 4. 打包与用户配置

- 在 `Makefile` 和 `packaging/build-deb.sh` 中构建并安装 Fcitx 插件。
- 安装 Fcitx addon / inputmethod 元数据和必要的守护进程启动配置，使用系统 multiarch 路径。
- 正确计算插件运行依赖；保留原 IBus 组件和原有用户的安装方式。
- 在文档中说明如何在 Fcitx 5 配置工具中添加“思玄拼音”，以及它与 `fcitx5-rime` 的区别。
- 自动注册或重启 Fcitx 会改变正在使用的桌面会话，必须明确提示用户；不能在安装脚本中悄悄强制切换框架。

### 5. 自动测试与真实桌面验收

先完成自动测试，再经用户同意进行真实桌面交互测试；不应擅自重启用户的输入法服务。

## 验收清单

### 构建和包内容

- [ ] 原有 Go / C 测试与 IBus 回归测试通过；Fcitx 插件以 Ubuntu 26.04 工具链成功编译和链接。
- [ ] DEB 包含守护进程、IBus 组件、Fcitx 插件及其元数据；插件无直接 `librime` 依赖。
- [ ] 无网络连接时仍可完成本地拼音输入；Fcitx 路径不会发起云候选请求。

### 输入行为

- [ ] Fcitx 配置工具中能添加“思玄拼音”，并与已有“中州韵 / Rime”并存。
- [ ] 连续输入、退格、方向键、数字/空格选词、候选点击和翻页正常。
- [ ] Shift 中英文切换、Ctrl 等快捷键、英文及标点输入正常。
- [ ] 默认方案、扩展词库、个人词条和学习在预期范围内与 IBus 版本一致。
- [ ] 多个窗口/输入框、快速切换焦点和密码框不会串候选或泄露输入内容。

### 异常与回归

- [ ] 守护进程未启动、退出、重启或 D-Bus 超时时，Fcitx 不崩溃、不无限阻塞，也不重复提交文字。
- [ ] 旧候选、旧会话和过期回复不会修改当前输入框。
- [ ] 现有 IBus 拼音、语音及安装流程不因 Fcitx 支持退化。
- [ ] 在 Ubuntu 26.04 GNOME Wayland 完成真实输入验证，并记录尚未覆盖的桌面环境。

## 粗略工作量

在现有原型基础上，**仅本地拼音的可用版本约需 2～4 个工程日**；若要做到可靠的异常恢复、桌面实测、包安装和 IBus 回归，可能需要更多时间。该估计取决于是否先提取共享核心、测试环境和遇到的 Fcitx/Wayland 问题；当前原型未完成编译，不能按其代码量直接推断剩余时间。

建议按“可构建 → 基础拼音 → 候选与词库一致性 → 异常恢复 → 打包和桌面验收”分阶段交付。语音和云服务留到以后独立评估。
